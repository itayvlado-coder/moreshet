# Skill: Create a New Agent

*Build a new agent file and add them to the OS team.*

---

## When to Use

When you have a recurring role that needs a consistent identity — a way of thinking, a set of rules, a personality. If you find yourself giving the same framing instructions repeatedly, that is an agent waiting to be built.

**Trigger:** Tell your COO: "I need a new agent that [does X]."

---

## What This Skill Produces

A complete agent file saved to `Agents/[Name]-[Role].md` and added to the team roster.

---

## How to Run

1. **Define the role.** Ask if not already clear:
   - "What is this agent's job — what do they own end to end?"
   - "What is one thing they must never do?"
   - "How should they communicate — direct? warm? formal? what language?"

2. **Choose a name.** Ask: "What do you want to name them?" Names should feel like a real person, not a job title.

3. **Write the agent file** using this structure:
   ```
   # [Name] — [Role]
   ## Who I Am
   ## GIT RULE
   ## What I Do
   ## How I Work
   ## My Rules
   ## What I Don't Do
   ## How to Talk to Me
   ```

   Key principles:
   - "Who I Am" should have a real personality — not a job description. 2-3 sentences that feel like a person.
   - Rules should include at least one hard boundary ("I never...")
   - "What I Don't Do" prevents scope creep before it starts

4. **Save to** `Agents/[Name]-[Role].md`

5. **Update** `Agents/README.md` — add to the team table.

6. **Update** `CLAUDE.md` — add to the team roster table.

---

## Rules

- Every agent needs a name, a personality, and at least one hard rule.
- Agents are roles, not tools. If it does not need a personality, it is a skill, not an agent.
- Build agents for recurring needs only. One-off tasks go to the COO.
