## Log

## 2026-07-20 — Real summary format is a timestamped log, not a thematic abstract
When we first designed the interview-summarization skill, the assumption was a "core essence + thematic tags" abstract. The real manual examples (Memory/summaries → moved to Brain/05-Interviews) showed the actual format needed: a chronological log segmented by location/event name, with MM:SS-MM:SS timestamp ranges per entry, referencing video/segment numbers. Always check for real examples before designing a content format from assumptions — the assumed format was structurally wrong even though the individual facts would have been correct.

## 2026-07-20 — External ASR transcripts work as well as (or better than) local Whisper
Local Whisper on this Intel Mac (CPU-only, no GPU) took over an hour to transcribe a single ~16-minute Hebrew interview with the "medium" model — impractical for ~20 interviews. An externally-transcribed VTT file (uploaded by the user) worked immediately and produced a usable, timestamped Hebrew transcript. Going forward, prefer external transcription tools when available; only fall back to local Whisper (`Tools/01-skills/transcribe-interview.md`) when no faster option exists. Any transcript format works as long as timestamps are preserved (SRT/VTT/JSON — not plain unstamped text).

## 2026-07-22 — New transcripts don't always arrive the same way, and the interviewee is often unnamed
Two more interviews were summarized this session, and neither arrived the way the pipeline assumed: one VTT showed up in `~/Downloads` (had to be copied into `Brain/05-Interviews/Season2-Lebanon/transcripts/` manually), the other was dropped directly into that transcripts folder without ever touching Downloads. When told "I uploaded a transcript," check both locations (and sort by mtime) rather than assuming one path. Separately, the ASR transcripts frequently never state the interviewee's name or rank on tape — it has to be inferred from context (who reports to whom, who they say they replaced, self-introduction attempts caught mid-take). When identity is inferred rather than stated, mark it clearly in the summary file (both a header note and a naming placeholder if unsure) and ask the user to confirm before treating the name as final — never silently commit to a guessed name.

## 2026-07-23 — `summary_md_to_docx.py` leaked literal `**` into Word output
The script's body-paragraph branch never parsed inline `**bold**` markdown — it just wrote the raw characters into the run, so every emphasized quote in a summary showed literal asterisks in the delivered `.docx`. This affected three files already sent to the CEO before it was caught (found by chance while reading a paragraph back to debug something else, not by a deliberate check). Fixed by splitting on `**` and toggling bold per segment (`add_run_with_inline_bold`), then regenerated and re-sent the affected files. Actionable: after any change to this script — or before trusting its output on a new document type — read a paragraph back via python-docx (or render to PDF if LibreOffice is available) rather than assuming the conversion matches the source markdown.

## 2026-07-23 — A later interview resolved an earlier one's unconfirmed identity — and filename numbers don't track story order

## 2026-09-24 — Weekly Givati reserve-duty activity report: how to fill it fast
Givati brigade requires a weekly "דו״ח עשייה שבועי – משרת מיל׳" for the reserve order under which the project work is done (order 01/07/2026 → expected end 01/01/2027, role: תחקירן). The form arrives as a CamScanner-scanned PDF with **no fillable fields**, so it has to be filled by drawing text onto the rendered page image (pypdfium2 render → PIL + python-bidi for Hebrew RTL, Arial font → save as PDF). Table columns: date / day / arrival / departure / daily activity / base-location. Standard entries: research days = "עבודת תחקיר", "משרדי הפרויקט, עלי"; graphics days = "עבודת גרפיקה", "משרדי הגרפיקאי, גדרה". Holidays (e.g. Yom Kippur) are left without hours but labeled in the activity column. Get exact hours per day from the CEO — never fill ranges or guessed times on an army report. Also: when a dictated term looks off (the CEO first wrote "גריפה", meant "גרפיקה"; "משרדי העורך" was actually "משרדי הגרפיקאי"), confirm before writing it into an official form.

## 2026-10-02 — Summaries from outside the pipeline: Drive zips, identity from the header line
A friend on the production wrote 15 interview summaries himself (brigade commander נתנאל שמכה, sayeret commander עמית, 52 battalion commander יול) and sent them as Google Drive "drive-download-*.zip" files. Two practical points. First, the Hebrew filenames inside these zips come out garbled with `unzip`; Python's `zipfile` plus a cp437→utf-8 re-decode of each name fixes it. Second, unlike our ASR transcripts, these summaries open with a "דובר: … | תפקיד: … | קובץ תמלול: …" line, so who is speaking can be read straight from the header instead of inferred. Surnames still may not be there: "לוי" (Amit) and "אור" (Yol) came from the user and from Yol's father on tape, not from the headers, and are marked as such. Stored one subfolder per interviewee under `summaries/` and cross-checked them against the outline (now v5).

## 2026-10-02 — Three commanders on the same event produce contradictions: list them, don't pick one
Once the brigade commander and two battalion commanders described the same moments, their accounts disagreed on concrete details: whether Yol stayed conscious, the hour the Litani climb started, where Dvash was killed, what the hospital is called. ## 2026-10-02 — Classified military material stays out of the repo
The CEO photographed an IDF briefing slide on a screen labeled "משואה – סודי ביותר" and asked for its routes to be drawn on a Google Earth screenshot. The CEO confirmed authorization, and the work was done entirely in the session scratchpad. Nothing from the slide went into the repo, because this repo syncs to GitHub, and the outline cites only the interviews, not the slide. Technique that worked: fit a similarity transform (scale, rotation, offset) from the two maps' shared landmarks, then verify it by overlaying the slide's extracted purple road lines on the satellite roads before drawing the green routes. For any future classified material: flag it, get explicit confirmation, keep it out of git, and remember that the route names in a phone photo of a screen are usually too blurry to read.

## 2026-10-02 — `summary_md_to_docx.py` also leaked single `*italic*` markers

## 2026-10-11 — Ceremony narration from classified slide photos: triage, verify, and check the partner's draft too
Givati asked for a 3-minute narration of the Lebanon maneuver for its excellence ceremony. The source was 217 phone photos of "משואה – סודי ביותר" presentation screens (Drive zip in ~/Downloads, kept out of the repo). What worked: contact sheets of 12 thumbnails to triage the many duplicate shots, then crops of only the ~25 slides that matter (per-phase summary, timeline, "מספרים מספרים", the fallen). Three lessons. (1) An official slide can be wrong by omission: Liav Kababia appeared without ז"ל and was in fact killed, so a missing honorific does not mean someone survived; ask. (2) Phase day counts add up to 103 even though the summary slide's "14.3–1.7" header does not match it; check the arithmetic before calling a source inconsistent. (3) The brigade's own draft had factual errors (car bombs instead of explosive drones, a crossing date one night early, "kilometers" of tunnel, a leftover work note "לפי הנתונים בתמלול המקורי"). A partner's text needs the same verification as our own. Historic claims need checking too: "first Litani crossing ever" was false (armor crossed in 1982), so the text says "first since 1982" and flags it.

## 2026-10-12 — Pushing to GitHub from this Mac: a classic token, not `gh`
The push failed with "Invalid username or token": the token stored in the macOS Keychain had expired. Don't install `gh` through Homebrew on this machine. It is an Intel Mac, which Homebrew has moved to Tier 3, so it builds Go and `gh` from source, which is slow and may fail. What worked: (1) erase the old credential with `printf "protocol=https\nhost=github.com\n\n" | git credential-osxkeychain erase`; (2) the CEO creates a **classic** Personal Access Token with the **repo** scope ticked (a fine-grained token, or one without that scope, authenticates but returns 403 "Permission denied"); (3) push from a real terminal, enter `itayvlado-coder` as the username and paste the token at the password prompt. The lock icon at that prompt and the absence of any characters on screen are normal. Paste only once. The Keychain then stores the token until it expires. Never ask the CEO to paste a token into the chat.

## 2026-10-21 — A citations spreadsheet maps best as event files, not person cards
Givati sent a צל״ש recommendations spreadsheet (10 tabs, each row a person with a first-person or recommender-written story). Many recipients fought in the same battle, and they sit in different tabs. For example, Shmuel Batit is listed under "קצינים בחוץ" but rode in the Sayeret commander's jeep at Nahal Oz. The approach that worked: download the xlsx through the Drive connector (the result is too large for context, so it is saved to a file); decode it and parse it with openpyxl in a scratchpad venv; dump every row without the phone columns; then keyword-search all rows for places and names to find who appears in whose story. Grouping by event cut duplicate interviews and turned up contradictions worth asking about on camera (who gave the order, timings, who fired first). Non-recipients named in the stories (residents, other units' officers, a random soldier made radio operator) belong in a "to locate" table.

## 2026-10-25 — Hebrew PDF export: two rendering traps
Markdown to HTML (Python-Markdown) to headless Chrome `--print-to-pdf` produces clean RTL PDFs, with two traps. (1) Python-Markdown does not render a list that directly follows a paragraph line unless there is a blank line between them. The converter now inserts one. (2) Number ranges like "7.10–9.10" render reversed inside RTL text, so write "7 עד 9 באוקטובר" or "11:00 עד 11:30" instead. Check by rendering a page to PNG and looking at it.

## 2026-11-06 — "סיפור המעשה" is two files: the story, and a key for the editor
After the 5.11 shoot the CEO asked to split the story of the deed into two files. (1) `<name> - סיפור המעשה` holds only the story of what the candidate went through, in order. (2) `<name> - רגעים למצלמה ומפתח לעורך` holds key lines with the interview timestamp, strong camera moments, directing notes, materials to request (for example the documentary "מז״ל טוב" that Dan Katzir appears in), and open contradictions. Use precise verbs: Ma'atuk *outfitted* (זיווד) a Namer, he did not *build* one. Identify people by full name and role ("דוד רון, סמח״ט גבעתי"). Pipeline that worked: ivrit-ai whisper-large-v3-turbo (ct2, int8) in a scratchpad venv on CommandLineTools Python 3.9, about 0.6× real time on this Intel Mac. Four interviews (4 hours of audio) ran overnight in sequence. Closing the lid paused the job and it resumed on wake.

## 2026-11-17 — Every new interview has to reach every layer, not only its own files

## 2026-11-17 — Battle-flow maps: OpenStreetMap through the main API, rendered to SVG
Overpass is unreliable from here (502/406). `https://api.openstreetmap.org/api/0.6/map?bbox=...` works for areas up to about 3×3 km, and a city like Sderot comes back at about 10 MB. For a wide area (the southern envelope), maps.mail.ru's Overpass mirror answered a roads-and-places query. The OSM Nova memorial layer (stage, bar, containers, police CP) gives real anchor points. Rendering in the deck's own colors keeps the slides consistent. The per-arena data lives in `battle_maps.py`, with an approximate flag per event, drawn as a hollow marker. Keep each map's height at 715 px or less, or the slide overflows. In inline SVG inside an RTL page, `text-anchor` behaves inconsistently, so set `direction="ltr"` and choose `end` or `start` explicitly. Give arrowhead marker ids a per-map prefix when several maps share a page.

## 2026-11-17 — PowerPoint and Google Slides animation from python-pptx
python-pptx has no animation API. Injecting a `<p:timing>` block after `clrMapOvr` works and passes the validator: one `<p:par>` per click, presets 10 (fade), 22 (wipe) and 53 (zoom), with exits using `presetClass="exit"`. Google Slides imports only fade, so the Google build maps wipe and zoom to fade. Internal links (`shape.click_action.target_slide`) on fully transparent rectangles over a screenshot make an overview slide clickable. Uploading the .pptx with conversion on turns it into a native Google Slides file. LibreOffice renders a static check, but the clicks themselves can only be verified in PowerPoint or Slides.

## 2026-11-22 — Converting transcripts to Word on this Mac
Neither pandoc nor python-docx is installed, and the docx npm package isn't installed globally. What worked: `npm install docx@9.5.1` in a scratchpad folder, then run the repo script with `NODE_PATH` pointing at it. LibreOffice's PDF render of the Word file hung past two minutes, so the check was done by unzipping `word/document.xml` and counting `[HH:MM:SS]` paragraphs against the md. All 16 matched (about 15,000 lines). Drive accepts a .docx uploaded with a file reference and conversion turned off, and it then stays a Word file the way the voice-note transcripts are.
